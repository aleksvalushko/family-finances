# 📘 План разработки: Family Budget PWA

> Семейное приложение для учёта финансов.  
> Стек: Next.js (App Router) + TypeScript + Tailwind CSS + Supabase (Auth, Postgres, Realtime) + PWA.  
> Режим работы: до 2 часов в день, Cursor в режиме `ask` (код пишешь сам, Cursor объясняет).

---

## 🎯 Общая стратегия

- **Не делай всё сразу.** Каждый этап — законченная маленькая победа.
- **Сначала ядро, потом украшения.** Ввод трат и баланс → real-time → PWA → графики → экспорт.
- **После каждого этапа** проси жену «потыкать» текущую версию. Это мотивация и фидбэк.
- **Cursor используй как учителя**, а не генератора. Спрашивай «почему», а не «напиши мне».

---

## 📦 Этап 0: Подготовка (30–60 минут, один вечер)

**Что сделать:**

1. Установить Node.js (если ещё нет).
2. Создать аккаунт на [supabase.com](https://supabase.com) (бесплатный тариф).
3. Создать новый проект в Supabase. Записать:
    - `Project URL`
    - `anon public key`
    - `service_role key` (хранить в секрете, не коммитить!)
4. Установить Cursor (уже есть) и убедиться, что режим `ask` активен.

**Что сказать Cursor (первый запрос):**

```text
Я начинаю новый проект: семейное приложение для учёта финансов (PWA) на Next.js App Router + TypeScript + Tailwind + Supabase.
Помоги мне составить чеклист первого этапа: создание проекта, установка зависимостей, настройка Supabase-клиента.
Не пиши код, просто перечисли шаги и объясни, зачем нужен каждый.
```

## 🏗️ Этап 1: Фундамент и аутентификация (3–4 вечера, ~6–8 часов)

**Цель:** Ты можешь зарегистрироваться, залогиниться и увидеть пустой экран «Привет, [имя]».

**Что сделать:**

- [ ] Создать Next.js проект: `npx create-next-app@latest family-budget --typescript --tailwind --eslint --app --src-dir`
- [ ] Установить зависимости: `npm i @supabase/supabase-js @supabase/ssr`
- [ ] Создать `.env.local` с ключами Supabase (URL + anon key).
- [ ] Настроить Supabase-клиент для Server и Client Components (по официальному гайду Supabase для Next.js).
- [ ] Создать страницы `/login` и `/register` с формами (email + пароль).
- [ ] Подключить Supabase Auth: `signUp`, `signInWithPassword`.
- [ ] Сделать middleware для защиты роутов (если не залогинен — редирект на `/login`).
- [ ] Создать главную страницу с приветствием и кнопкой «Выйти».

**Что сказать Cursor:**

```text
Я настраиваю Supabase Auth в Next.js App Router (TypeScript).
Объясни разницу между @supabase/supabase-js и @supabase/ssr.
Как правильно создать клиент для Server Components, Client Components и middleware?
Покажи минимальный пример логина через signInWithPassword и защиту роута через middleware.
```

**Критерий готовности:** Ты можешь зарегистрироваться, войти, увидеть главную и выйти.

## 🗄️ Этап 2: База данных и RLS (2–3 вечера, ~4–6 часов)

**Цель:** В базе есть таблицы для семей и транзакций, настроен доступ по `family_id`.

**Что сделать:**

- [ ] В Supabase SQL Editor создать таблицы:
    - `families` (id, name, created_at)
    - `profiles` (id = auth.uid(), family_id, display_name)
    - `categories` (id, family_id, name, icon, type)
    - `transactions` (id, family_id, user_id, amount, type, category_id, note, created_at)
- [ ] **Сразу включить RLS** на всех таблицах: `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;`
- [ ] Написать политики:
    - `profiles`: пользователь видит только свой профиль и профили своей семьи.
    - `categories`: только категории своей семьи.
    - `transactions`: только транзакции своей семьи.
- [ ] Настроить триггер: при регистрации автоматически создавать `profile`.
- [ ] Создать функцию/триггер для создания «семьи» при первом входе (или экран «Создать семью / Присоединиться по коду»).

**Что сказать Cursor:**

```text
У меня есть таблицы families, profiles, categories, transactions в Supabase (Postgres).
Помоги написать RLS-политики так, чтобы пользователь видел только данные своей семьи (family_id).
Объясни, как работает auth.uid() в политиках и почему это безопасно.
Покажи пример политики для SELECT, INSERT, UPDATE, DELETE на таблице transactions.
```

**Критерий готовности:** В Supabase ты видишь свои данные, а «чужой» пользователь (создай тестовый) их не видит.

**⚠️ Важно:** Не переходи к Этапу 3, пока RLS не работает. Это фундамент безопасности.

## 💸 Этап 3: Ядро — добавление трат и баланс (4–5 вечеров, ~8–10 часов)

**Цель:** Можно добавить трату/доход, увидеть список последних транзакций и баланс за месяц.

**Что сделать:**

- [ ] Главный экран: крупный баланс за месяц (доходы − расходы).
- [ ] Кнопка «+» (плавающая, внизу по центру).
- [ ] Bottom sheet (шторка) для добавления транзакции:
    - Поле суммы (цифровая клавиатура).
    - Переключатель «Расход / Доход».
    - Сетка иконок категорий.
    - Кнопка «Сохранить».
- [ ] Server Action (или клиентская мутация) для вставки в `transactions`.
- [ ] Список последних 5–10 транзакций под балансом.
- [ ] Подсчёт баланса: SQL-запрос с `SUM` по `type` и фильтром по месяцу, либо агрегация на клиенте.

**Что сказать Cursor:**

```text
Мне нужно добавить транзакцию в Supabase из Next.js App Router.
Объясни разницу между Server Action и клиентской мутацией через supabase-js.
Что лучше для формы с валидацией и мгновенным обновлением UI?
Покажи минимальный пример Server Action для INSERT в таблицу transactions.
```

**Критерий готовности:** Ты вносишь трату, она появляется в списке, баланс пересчитывается.

## ⚡ Этап 4: Real-time синхронизация (2–3 вечера, ~4–5 часов)

**Цель:** Жена добавила трату — у тебя на телефоне она появилась без перезагрузки.

**Что сделать:**

- [ ] Включить Realtime для таблицы `transactions` в настройках Supabase.
- [ ] На клиенте подписаться на изменения: `supabase.channel('transactions').on('postgres_changes', ...)`.
- [ ] Обновлять локальный стейт (React Query / SWR / useState) при получении события.
- [ ] Добавить оптимистичное обновление: при добавлении траты сначала показываем в UI, потом сохраняем. Если ошибка — откатываем.
- [ ] Протестировать: два браузера (или два устройства) под разными аккаунтами.

**Что сказать Cursor:**

```text
Я подписываюсь на Supabase Realtime для таблицы transactions.
Объясни, как правильно отписываться при размонтировании компонента (cleanup).
Как совместить real-time с оптимистичным обновлением UI, чтобы не было двойных записей?
Покажи пример с useEffect и cleanup.
```

**Критерий готовности:** Изменения появляются у обоих пользователей в реальном времени.

- [ ] Установить `next-pwa` или `@serwist/next`.
- [ ] Создать `manifest.json`: название, иконки (192x192, 512x512), `display: standalone`, `theme_color`.
- [ ] Настроить Service Worker: кэширование статики и последних данных.
- [ ] Проверить установку на iPhone: Safari → «Поделиться» → «На экран "Домой"».
- [ ] Проверить, что при запуске нет адресной строки.

**Что сказать Cursor:**

```text
Я настраиваю PWA для Next.js App Router с @serwist/next.
Объясни, какие стратегии кэширования использовать для статики и для API-запросов к Supabase.
```

**⚠️ Нюанс:** Push-уведомления на iOS работают **только** если PWA установлено на домашний экран через Safari.
