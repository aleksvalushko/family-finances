# 📘 План разработки: Family Finances PWA

> Семейное приложение для учёта финансов.  
> Репозиторий: `family-finances`.  
> Стек: Next.js 16 (App Router) + TypeScript + Tailwind CSS + Supabase (Auth, Postgres, Realtime) + PWA.  
> Режим работы: до 2 часов в день, Cursor чаще в режиме `ask` (код пишешь сам, Cursor объясняет).

### README и NOTES — разные роли

| Файл                      | Роль                                                                            |
| ------------------------- | ------------------------------------------------------------------------------- |
| **README.md** (этот файл) | Полный план проекта: этапы 0–8, цели, чеклисты, критерии, что спросить у Cursor |
| **NOTES.md**              | Дневник: что уже сделано, очередь на ближайшие дни, handoff работа ↔ дом        |

Где ты сейчас по дням — смотри только в `NOTES.md`. Здесь галочки этапов — это «что должно быть сделано для закрытия этапа», а не отметки сегодняшнего вечера.

## 🎯 Общая стратегия

- **Не делай всё сразу.** Каждый этап — законченная маленькая победа.
- **Сначала ядро, потом украшения.** Auth → БД/RLS → ввод трат и баланс → real-time → PWA → графики → экспорт.
- **После каждого этапа** проси жену «потыкать» текущую версию. Это мотивация и фидбэк.
- **Cursor используй как учителя**, а не генератора. Спрашивай «почему», а не «напиши мне весь проект».

## 📦 Этап 0: Подготовка (30–60 минут, один вечер)

**Цель:** Node, аккаунт Supabase, ключи, Cursor.

**Что сделать:**

1. Установить Node.js (LTS), если ещё нет.
2. Создать аккаунт на [supabase.com](https://supabase.com) (бесплатный тариф).
3. Создать новый проект в Supabase. Записать:
    - `Project URL`
    - публичный ключ (**publishable** / в старых текстах часто называют **anon**)
    - `service_role key` (только в секретном месте; не коммитить; не класть в `NEXT_PUBLIC_*`)
4. Cursor уже есть; для учёбы удобен режим `ask`.

**Что сказать Cursor (если начинаешь с нуля):**

```text
Я начинаю новый проект: семейное приложение для учёта финансов (PWA) на Next.js App Router + TypeScript + Tailwind + Supabase.
Помоги составить чеклист первого этапа: создание проекта, зависимости, настройка Supabase-клиента.
Не пиши код, просто перечисли шаги и объясни, зачем нужен каждый.
```

**Критерий готовности:** есть URL и публичный ключ; понятно, что service role в клиент не идёт.

> Если этап 0 уже пройден — не возвращайся сюда. Актуальный шаг смотри в `NOTES.md`.

## 🏗️ Этап 1: Фундамент и аутентификация (3–4 вечера, ~6–8 часов)

**Цель:** зарегистрироваться, войти и увидеть экран «Привет, [имя]», затем выйти.

**Что сделать:**

- [x] Создать Next.js проект (App Router, TypeScript, Tailwind, ESLint, `src-dir`), например:
      `npx create-next-app@latest family-finances --typescript --tailwind --eslint --app --src-dir`
- [x] Установить зависимости: `npm i @supabase/supabase-js @supabase/ssr`
- [x] Создать `.env.local` (не коммитить):
    - `NEXT_PUBLIC_SUPABASE_URL`
    - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`  
      (имя переменной должно совпадать с кодом; значение — публичный ключ из Dashboard)
- [x] Настроить клиенты по гайду Supabase для Next.js:
    - `src/lib/supabase/client.ts` — браузер (Client Components)
    - `src/lib/supabase/server.ts` — Server Components / Server Actions / Route Handlers
    - `src/lib/supabase/proxy.ts` — `updateSession` (обновление auth-cookies)
    - `src/proxy.ts` — вход для **Next.js 16** (в старых гайдах это был `middleware.ts` на Next ≤15)
- [x] Smoke: приложение стартует; с сервера вызывается `getClaims()` без ошибок env/ключа (до логина claims могут быть пустыми)
- [ ] Страницы `/login` и `/register` (email + пароль)
- [ ] Supabase Auth: `signUp`, `signInWithPassword`, `signOut`
- [ ] Защита роутов: если гость — редирект на `/login` (добавлять в `updateSession`, когда страницы login уже есть)
- [ ] Главная: приветствие и кнопка «Выйти»

**Что сказать Cursor:**

```text
Я настраиваю Supabase Auth в Next.js 16 App Router (TypeScript).
Объясни разницу между @supabase/supabase-js и @supabase/ssr.
Как правильно сделать client, server и proxy (updateSession + src/proxy.ts)?
Почему на сервере лучше getClaims, а не getSession?
Покажи минимальный пример login через signInWithPassword и редирект гостя на /login.
```

**Критерий готовности:** регистрация → вход → главная с приветствием → выход.

**Не переходи к этапу 2**, пока критерий этапа 1 не выполнен.

## 🗄️ Этап 2: База данных и RLS (2–3 вечера, ~4–6 часов)

**Цель:** в базе есть таблицы для семей и транзакций, доступ ограничен по `family_id`.

**Что сделать:**

- [ ] В Supabase SQL Editor создать таблицы:
    - `families` (id, name, created_at)
    - `profiles` (id = auth.uid(), family_id, display_name)
    - `categories` (id, family_id, name, icon, type)
    - `transactions` (id, family_id, user_id, amount, type, category_id, note, created_at)
- [ ] **Сразу включить RLS** на всех таблицах: `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;`
- [ ] Написать политики:
    - `profiles`: свой профиль и профили своей семьи
    - `categories`: только категории своей семьи
    - `transactions`: только транзакции своей семьи
- [ ] Триггер: при регистрации автоматически создавать `profile`
- [ ] Создание «семьи» при первом входе или экран «Создать семью / Присоединиться по коду»

**Что сказать Cursor:**

```text
У меня есть таблицы families, profiles, categories, transactions в Supabase (Postgres).
Помоги написать RLS-политики так, чтобы пользователь видел только данные своей семьи (family_id).
Объясни, как работает auth.uid() в политиках и почему это безопасно.
Покажи пример политики для SELECT, INSERT, UPDATE, DELETE на таблице transactions.
```

**Критерий готовности:** свои данные видны; у тестового «чужого» пользователя — нет.

**⚠️ Важно:** не переходи к этапу 3, пока RLS не работает. Это фундамент безопасности.

## ✅ Чеклист «не забыть»

- [ ] RLS включён на **всех** таблицах с первого появления схемы.
- [ ] `service_role key` **никогда** не попадает в клиентский код и в Git.
- [ ] `.env.local` в `.gitignore` (у нас игнорируются `.env*`).
- [ ] Имя публичного ключа в коде и в `.env.local` одно и то же: `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- [ ] Next.js 16: сессия через `src/proxy.ts` + `updateSession`. Старые гайды про `middleware.ts` относятся к Next ≤15 — не копировать слепо.
- [ ] На сервере для проверки пользователя предпочитать `getClaims()`, не доверять сырому `getSession()` из cookie.
- [ ] Оптимистичное обновление UI — чтобы приложение ощущалось быстрым.
- [ ] Тап-зоны ≥44px на мобилке.
- [ ] PWA-манифест с иконками 192 и 512.
- [ ] Push-уведомления на iOS — только после установки на домашний экран.
- [ ] После логического куска — коммит и пуш на GitHub (перед сменой компа или облачным ревью).
- [ ] Раз в неделю — фидбэк от жены.
- [ ] На бесплатном тарифе Supabase база «засыпает» после неактивности. Для семейного приложения это обычно не проблема (вы заходите регулярно). Если проект встанет на паузу — зайди в Dashboard, чтобы разбудить проект.
